## 3. APPENDIX B — GEMINI'S FIVE TETHER-EFFECT ASSUMPTIONS, RECONCILED

Source: Gemini's return, §(c) "For the Hub — Tether Effects"
(`Gemini_Seat_Tether_Round_Spec__20261110.pdf`). **This appendix is
reconciliation only** — it records where the other returns agree, conflict, or
are silent. Nothing here rules an assumption true or false; Damien's override
stands.

**B1. Transport unidirectionality (dependency on Claude's seat).**
Gemini assumes Claude's transport supports store-and-forward, node-initiated
outbound delivery with no open inbound port, no remote wake, no hub-initiated
polling on the node; if Claude's transport requires hub-to-node ACKs over a
bidirectional socket, the no-tether boundary must be reviewed.
*Reconciliation: AGREES with Claude's return.* Claude's routing is hub-mediated
throughout — destination is an envelope field, everything routes via the hub,
artefacts travel as files or pasted blocks in an envelope (GROVE-ENVELOPE v1);
nothing in Claude's spec requires an inbound socket or a polling loop on the
node. ChatGPT's return is silent on transport direction (its line is the vault).
Perplexity: not applicable to its assignment.

**B2. Hub-side NO SIGNAL state synthesis (dependency on the hub).**
The resident never emits a "dead" packet; the hub must run the timer logic
that converts missing interval reports into an explicit NO SIGNAL status
instead of displaying the last cached NOMINAL state.
*Reconciliation: AGREES with Claude's return, strongly.* Claude's C7
(absence is data) transfers to circuit traffic unchanged in its Stage 4:
every EXPECTED-but-absent artefact posts NO SIGNAL at its station; the hub's
circuit checkpoint carries the same state machine (EXPECTED-but-absent at
audit → NO SIGNAL, never silently awaited); a missed resident report is
named by Claude as a NO SIGNAL posting under the same rule. Perplexity's
guard discipline agrees in kind (no sourced-looking grade may be manufactured
for an absent item). No conflict found.

**B3. Checkpoint rollback sequence reconciliation (dependency on hub & ledger seats).**
After an owner-initiated checkpoint restore, the resident's
ledger_chain_head_seq legitimately moves backward; seats tracking monotonic
sequence numbers must honor the CHECKPOINT_RESTORED event and the
boot_generation counter rather than permanently quarantining the node.
*Reconciliation: TENSION with Claude's return — unresolved, flagged, not settled
here.* Claude's restore rules include a rollback guard: a checkpoint whose
epoch is older than the newest epoch already seen is REFUSED, and restore
goes *to* the checkpoint, never silently past it, with post-checkpoint entries
surfaced for the owner to re-post on purpose. Gemini's mechanism answers a
different half of the same event — the *reporting* sequence after a legitimate
owner restore — via a boot_generation counter stored outside the rolled-back
dataset. The two are compatible only if the epoch/boot_generation semantics
are unified (an owner-consented restore re-anchoring validation, per Claude's
custody-and-consent rule, vs. an unconsented rollback, which Claude refuses).
Neither return performs that unification. ChatGPT's return touches the same
boundary from the vault side — it named the vault-to-transport
checkpoint/restore boundary its weakest tether and left Entry 61–63 survival
NOT YET VERIFIED — which is consistent with this joint being genuinely open.
**This is the one assumption where reconciliation finds an open seam, and it
sits on the joint two other seats independently named weakest.**

**B4. Deterministic host-side telemetry (dependency on seat harness/runtime).**
State reports are generated by deterministic host-level code, not LLM prompt
generation; other seats can rely on strict JSON schema compliance even under
the smaller-voice or model-agnostic branches, though seated_voice.capabilities
may shrink to [] between model swaps.
*Reconciliation: AGREES in method with Claude; ONE key-form divergence flagged.*
Claude's transport is likewise deterministic code (its reference model,
transport_ref.py, is the spec stated as executable code, with conformance
vectors), so the method assumption holds across both returns. Divergence:
the two returns specify **different canonical key forms** — Gemini's report
key is `seat:gemini:<node_uuid>:<ledger_chain_head_seq>:<epoch_ms>`, while
Claude's canonical key is (domain-segment, extraction-string) under
GROVE-ADDR-v1, with the terminator excluded, and Claude rules that circuit
artefacts are addressed with that same grammar ("no second naming system
exists to drift"). Gemini's key form is not expressed in Claude's grammar.
Flagged as a divergence for Damien's attention; reconciliation does not pick
a winner.

**B5. Pre-gate human-in-the-loop latency (dependency on workflow/orchestration seats).**
While SUPERVISED_TEST_MODE is active, on-request status checks require the
owner to act locally at the node ("through the owner's door"); on-demand
queries are asynchronous, human-gated, unbounded-latency — never synchronous RPC.
*Reconciliation: AGREES with Claude's return and with the circuit's standing
shape.* Claude's design assumes Damien as the physical bus — every byte
between a seat and the hub moves through his hands — and its resume-card
mechanism exists precisely because seat continuity is human-carried. Gemini's
own cadence rules (B-appendix of its return) forbid hub-initiated remote pull
and allow on-request checks only through the owner's door. No return
contradicts this assumption. Perplexity and ChatGPT: silent (outside their
assignments), which is not disagreement.

**Cross-cutting note.** Claude and Perplexity independently named the same
weakest joint — the hub's carry-forward (Claude: the summary a return is
folded into, checked against itself; Perplexity: a qualified finding losing
its limits as it becomes the next premise list). Gemini named a different
weakest tether (the async boundary between Ledger Store verification and
